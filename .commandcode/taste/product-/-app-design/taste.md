# Product / App Design
- For the photo-sorter, user explicitly wants per-folder actions — review, grouping, tournament, and export scoped to a single selected folder at a time, not whole-library operations. He wants to separate photos into small actionable chunks ("anything greater than one folder is too much"; "I am lazy"). Confidence: 0.9
- User wants fast, incremental testing loops: while testing is ongoing, avoid full-library scans (e.g., 15k photos) and support scanning/testing one small folder at a time so issues surface quickly without waiting for a huge scan. Confidence: 0.85
- User expects production data migrations to handle upgrading an existing deployed database, not just fresh setups — the assistant should add regression tests that reproduce the deployed scenario (old schema/DB) before pushing a fix. Confidence: 0.6
- When a previous project attempt already has a good/polished interface, user prefers the assistant to read and reuse that prior UI work rather than rebuild the interface from scratch — the prior attempt's problems were infrastructure/dockerization, not the UI. Confidence: 0.6
- For the photo-sorter review workflow, user wants to judge photos fairly: thumbnails must be sharp enough to judge (256px was "too blurry to judge photos fairly"; bumped to 512px/q85) and groups should carry enough context (~4 photos) rather than many isolated 1-photo groups — both were raised as blocking UX defects in group review. Confidence: 0.6
- User expects long-running operations (scan/analyze/group) to surface visible progress in the UI — reporting "the interface tells me nothing on progress" treats a silent UI as a UX defect even when the backend work completes quickly; background-job + SSE progress must be rendered as a visible bar/row in the interface. Confidence: 0.6
- User expects the app UI to visibly show progress during long-running operations — reporting "the interface tells me nothing on progress" while a re-scan runs treats a silent UI as a UX defect, not just a backend concern (background jobs + SSE must surface as a visible progress bar/row in the UI). Confidence: 0.6
